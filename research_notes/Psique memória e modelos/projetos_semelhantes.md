# Amelia 4 — Similar Projects and Reusable Components

Research snapshot: 24 October 2026. Primary repositories, official documentation, and papers are preferred; repository stars are approximate point-in-time activity signals, not quality measures.

## How do the named chat, memory, agent, and companion products approach chat, persona, memory, and agents?

### Takeaway
The landscape separates into four layers: chat/workbench products, memory infrastructure, agent orchestration, and closed companion products. No named product combines all of Amelia's proposed local-first identity, inspectable autobiographical memory, cognitive/psychological pipeline, curated academy, and optional personal fine-tuning.

### Cited Findings
- **Open WebUI** is a self-hosted, offline-capable chat platform for Ollama and OpenAI-compatible endpoints. Its memory bank stores typed/path-addressed snippets; users and models can add, search, replace, move, or delete memories. It also has arena/Elo evaluation and rated-chat snapshots, but integrated dataset construction and fine-tuning remain roadmap items. Its current license is source-available with a branding condition, not standard OSI open source. — [Repository](https://github.com/open-webui/open-webui/); [memory docs](https://docs.openwebui.com/features/chat-conversations/memory.md); [evaluation docs](https://docs.openwebui.com/features/administration/evaluation/); [roadmap](https://docs.openwebui.com/roadmap.md); [license](https://github.com/open-webui/open-webui/blob/main/LICENSE)
- **LibreChat** is an active MIT project (about 46.2k stars and 9.5k forks at the snapshot) providing multi-provider/local-model chat, agents, MCP, skills, subagents, file search, code execution, and durable agent controls. Its user memory is an opt-in, editable key/value store injected into requests—not semantic search over all chat history—and can be partitioned per agent. — [Repository](https://github.com/danny-avila/LibreChat/); [memory docs](https://www.librechat.ai/docs/features/memory); [agent docs](https://www.librechat.ai/docs/features/agents); [Docker architecture](https://www.librechat.ai/docs/local/docker)
- **AnythingLLM** is an MIT local-first desktop/server product (about 67.3k stars and 7.5k forks) with a built-in llama.cpp-based engine, Ollama/LM Studio integrations, document workspaces, RAG, user-managed and automatic memories, no-code agents, MCP, and scheduled tasks. Desktop is strongest for a single local user; multi-user controls require Docker. — [Repository](https://github.com/Mintplex-Labs/anything-llm/); [self-hosted terms](https://github.com/Mintplex-Labs/anything-llm/blob/master/TERMS_SELF_HOSTED.md); [local engine](https://docs.anythingllm.com/setup/llm-configuration/local/built-in); [installation comparison](https://docs.anythingllm.com/installation-docker/overview)
- **Khoj** is an AGPL-3.0 “second brain” (about 37.8k stars and 2.5k forks) supporting local/hosted models, semantic search over notes and documents, custom agents with persona/knowledge/tools, and automations across browser, desktop, Obsidian, Emacs, mobile, and WhatsApp. Its center of gravity is personal knowledge retrieval rather than a continuously evolving companion identity. — [Repository](https://github.com/khoj-ai/khoj/); [chat docs](https://docs.khoj.dev/features/chat); [OpenAI-compatible/local proxy](https://www.mintlify.com/khoj-ai/khoj/advanced/openai-proxy)
- **LobeChat** is Apache-2.0 and supports Ollama, configurable agents, knowledge bases, and local or server-side databases; its experimental local database uses CRDTs for multi-device synchronization. It is a polished interaction shell, but its architectural emphasis is model/provider UX rather than a psychologically modeled persistent self. — [Repository/README](https://github.com/lobehub/lobe-chat); [license](https://github.com/lobehub/lobe-chat/blob/main/LICENSE)
- **Letta** (formerly MemGPT) treats an agent as a persistent entity. Always-visible memory blocks such as `persona` and `human` can be autonomously edited by the agent; archival memory is semantically searched outside context and can be inserted/search by agents and fully managed by developers. The current SDK additionally models memory as git-backed files through MemFS. Letta is Apache-2.0. — [Memory blocks](https://docs.letta.com/v1-sdk/memory/memory-blocks/index.md); [archival memory](https://docs.letta.com/v1-sdk/memory/archival-memory/); [current memory/MemFS](https://docs.letta.com/agent-sdk/memory/index.md); [repository](https://github.com/letta-ai/letta); [license](https://github.com/letta-ai/letta/blob/main/LICENSE)
- **Mem0** is an Apache-2.0 memory layer rather than a full companion. OSS SDK/server operations include add/search/update/delete, expiration metadata, filtered deletion, and per-memory history; identity can be scoped by user, agent, and run. Its API-first design is easier to embed than a full agent runtime. — [Repository](https://github.com/mem0ai/mem0); [update](https://docs.mem0.ai/core-concepts/memory-operations/update); [delete](https://docs.mem0.ai/core-concepts/memory-operations/delete); [OSS REST server](https://docs.mem0.ai/open-source/features/rest-api); [license](https://github.com/mem0ai/mem0/blob/main/LICENSE)
- **Zep/Graphiti** has split into a proprietary hosted Zep service and Apache-2.0 **Graphiti**, an open framework (about 32.2k stars and 3.3k forks) for temporal context graphs. Graphiti incrementally ingests episodes, records provenance and changing validity, and combines semantic, keyword, and graph retrieval; users must supply graph database, model, embedder, tenancy, and operations. — [Graphiti repository](https://github.com/getzep/graphiti); [official overview](https://help.getzep.com/graphiti/getting-started/welcome.mdx); [license](https://github.com/getzep/graphiti/blob/main/LICENSE); [Zep hosted terms](https://www.getzep.com/legal/terms/)
- **LangGraph** is an MIT low-level state-machine/runtime for long-running agents. It offers durable execution, checkpoints, inspectable/modifiable state, human-in-the-loop control, and short- and long-term memory, while deliberately not prescribing prompts or a cognitive architecture. — [Official overview](https://docs.langchain.com/oss/python/langgraph/overview); [repository](https://github.com/langchain-ai/langgraph); [license](https://github.com/langchain-ai/langgraph/blob/main/LICENSE)
- **CrewAI** is an active MIT framework (about 60.1k stars and 8.9k forks) emphasizing role-playing agent crews and event-driven flows. Flows persist state to SQLite by default; unified memory persists to LanceDB and scores semantic similarity, recency, and importance. — [Repository](https://github.com/crewAIInc/crewAI); [flows](https://docs.crewai.com/v1.15.28/en/concepts/flows); [memory](https://docs.crewai.com/edge/en/concepts/memory)
- **AutoGen** is now archived and explicitly not recommended by Microsoft for production; no bug or security fixes are promised. Its MIT multi-agent ideas were folded into Microsoft Agent Framework. — [Archived repository notice](https://github.com/microsoft/autogen/)
- **Semantic Kernel** remains MIT and has about 28.7k stars, but receives minimal security and bug fixes; Microsoft directs new agent work to **Microsoft Agent Framework 1.0**, which combines Semantic Kernel foundations with AutoGen orchestrations and supports Ollama, durable workflows, checkpointing, pluggable memory, and multi-agent patterns. — [Semantic Kernel repository](https://github.com/microsoft/semantic-kernel); [maintenance change](https://github.com/microsoft/semantic-kernel/pull/13932); [Agent Framework 1.0](https://devblogs.microsoft.com/agent-framework/microsoft-agent-framework-version-1-0/); [Agent Framework repository](https://github.com/microsoft/agent-framework/)
- **Replika** is hosted-only and closed-source. It exposes a Memory screen where users can inspect and remove learned facts; it remembers profile details, interests, people, and pets. Its privacy policy says conversation content is not used for marketing, while conversations are processed to personalize the service. — [Memory help](https://help.replika.com/hc/en-us/articles/360000874712-What-does-my-Replika-remember-about-me); [privacy policy](https://replika.com/legal/privacy/en)
- **Nomi** is hosted-only and closed-source. It layers short-, medium-, and long-term memory with Identity Core, Backstory+, and a per-chat Mind Map. Mind Map dossiers are searchable, editable, lockable, prioritized summaries, but underlying memories cannot be edited or removed by users. — [Mind Map 2.0](https://wiki.nomi.ai/Mind_Map_2.0); [memory/editing distinction](https://wiki.nomi.ai/Are_Mind_Map_Entries_Memories%3F); [formation behavior](https://wiki.nomi.ai/How_is_information_added_to_Mind_Maps%3F)
- **Kindroid** is hosted-only and closed-source. Its companion configuration includes backstory, directives, key memories, learned context, chat history, proprietary medium-term memory, retrievable long-term memory, and journal entries; several deeper layers are subscriber-only. — [Official memory docs](https://kindroid.ai/v2/docs/memory/)

### Inferences
- Use a chat shell as reference or an interchangeable client, not as Amelia's domain model. The chat products optimize provider access, documents, and tools; their “persona” is typically configuration text plus memories.
- Letta is the closest reusable model for persistent identity and self-editable internal state. Mem0 is the simplest embeddable CRUD memory service; Graphiti is strongest when temporal contradiction and relationship history matter.
- Companion products demonstrate that visible memory controls, stable identity notes, and layered recall are user-facing features, not backend details. Amelia should expose provenance and correction more deeply than Nomi, whose underlying memories remain opaque.

### Gaps
- Closed companion vendors do not publish enough architecture to verify retrieval algorithms, model adaptation, or reliability claims.
- Repository metadata could not be collected uniformly for every project; activity numbers above are included only where a live repository result exposed them.
- None of the sources establishes a comparable, independent benchmark across these products' long-term recall.

## Which open-source projects support local models, durable memory, memory editing, file ingestion, evaluations, or training-data workflows?

### Takeaway
Local inference, file ingestion, RAG, and generic durable execution are mature commodities. Human-editable memory is available but inconsistent. Evaluation-to-curated-dataset-to-local-training remains fragmented and is the clearest missing integrated workflow.

### Cited Findings
- **Local models:** Open WebUI, LibreChat, AnythingLLM, Khoj, and LobeChat all connect to Ollama or OpenAI-compatible local servers; AnythingLLM also embeds a llama.cpp-based local engine. Letta and orchestration frameworks can use local endpoints but are not model runtimes. — [Open WebUI repository](https://github.com/open-webui/open-webui/); [LibreChat repository](https://github.com/danny-avila/LibreChat/); [AnythingLLM local engine](https://docs.anythingllm.com/setup/llm-configuration/local/built-in); [Khoj proxy](https://www.mintlify.com/khoj-ai/khoj/advanced/openai-proxy); [LobeChat README](https://github.com/lobehub/lobe-chat)
- **Durable memory/editing:** Open WebUI offers manual and model-managed add/search/update/delete; LibreChat offers manual key/value editing and agent tools; AnythingLLM advertises automatic and user-managed memories; Letta exposes editable core blocks plus developer-managed archival passages; Mem0 exposes CRUD and history; Graphiti stores temporally valid graph facts. — [Open WebUI memory](https://docs.openwebui.com/features/chat-conversations/memory.md); [LibreChat memory](https://www.librechat.ai/docs/features/memory); [AnythingLLM repository](https://github.com/Mintplex-Labs/anything-llm/); [Letta memory blocks](https://docs.letta.com/v1-sdk/memory/memory-blocks/index.md); [Mem0 REST API](https://docs.mem0.ai/open-source/features/rest-api); [Graphiti repository](https://github.com/getzep/graphiti)
- **File ingestion:** AnythingLLM distinguishes thread attachments from workspace-embedded RAG documents. LibreChat offers full-text upload, semantic file search, code-interpreter files, and persistent file context. Khoj indexes PDF, Markdown, org-mode, Word, Notion, images, and notes. Letta can attach external data sources and documents to archival memory. — [AnythingLLM document docs](https://docs.anythingllm.com/chatting-with-documents/introduction); [LibreChat agent/file docs](https://www.librechat.ai/docs/features/agents); [LibreChat text-upload pipeline](https://www.librechat.ai/docs/features/upload_as_text); [Khoj repository](https://github.com/khoj-ai/khoj/); [Letta architecture](https://www.letta.com/blog/introducing-the-agent-development-environment/)
- **Evaluation:** Open WebUI provides blind arena comparisons, thumbs up/down, Elo leaderboards, and chat snapshots. Its own docs say future fine-tuning use is still being developed, and maintainers state feedback does not automatically train models. — [Evaluation docs](https://docs.openwebui.com/features/administration/evaluation/); [maintainer answer](https://github.com/open-webui/open-webui/discussions/2810); [roadmap](https://docs.openwebui.com/roadmap.md)
- **Training workflows:** Apache-2.0 LLaMA-Factory supports SFT, reward modeling, DPO/KTO/ORPO/PPO, LoRA/QLoRA, local or hub datasets, experiment tracking, inference, and adapter merge/export; it has about 75.7k stars and 9.3k forks. Apache-2.0 Axolotl similarly covers preprocessing, SFT, preference tuning, evaluation, quantization, and inference from YAML, with conversation and instruction dataset formats. — [LLaMA-Factory repository](https://github.com/hiyouga/LLaMA-Factory/); [LLaMA-Factory license](https://github.com/hiyouga/LLaMA-Factory/blob/main/LICENSE); [Axolotl docs](https://docs.axolotl.ai/); [Axolotl dataset formats](https://docs.axolotl.ai/docs/dataset-formats/)
- **License summary:** permissive options include LibreChat/AnythingLLM/LangGraph/CrewAI/Semantic Kernel/Microsoft Agent Framework (MIT) and LobeChat/Letta/Mem0/Graphiti/LLaMA-Factory/Axolotl (Apache-2.0). Khoj is AGPL-3.0. Open WebUI's additional branding requirement makes it unsuitable as an unexamined white-label foundation. AutoGen is MIT but archived. — [LibreChat license](https://github.com/danny-avila/LibreChat/blob/main/LICENSE); [AnythingLLM license](https://github.com/Mintplex-Labs/anything-llm/blob/master/LICENSE); [LangGraph license](https://github.com/langchain-ai/langgraph/blob/main/LICENSE); [CrewAI repository](https://github.com/crewAIInc/crewAI); [Semantic Kernel repository](https://github.com/microsoft/semantic-kernel); [LobeChat license](https://github.com/lobehub/lobe-chat/blob/main/LICENSE); [Letta license](https://github.com/letta-ai/letta/blob/main/LICENSE); [Mem0 license](https://github.com/mem0ai/mem0/blob/main/LICENSE); [Graphiti license](https://github.com/getzep/graphiti/blob/main/LICENSE); [Khoj license](https://github.com/khoj-ai/khoj/blob/master/LICENSE); [Open WebUI license](https://github.com/open-webui/open-webui/blob/main/LICENSE)

### Inferences
- Amelia can avoid inventing model serving, vector indexing, document parsing, adapter training, and generic workflow checkpointing.
- The academy should be its own first-class subsystem: explicit source licensing, examples, exclusions, revisions, user approval, train/test splits, export formats, and lineage from chat/memory to dataset row to adapter version.
- A memory UI should distinguish raw evidence, extracted fact, autobiographical episode, relationship interpretation, persona commitment, and training candidate. Existing products tend to flatten these categories.

### Gaps
- No reviewed open-source chat product provides a mature end-to-end loop from user correction through privacy review, dataset curation, regression evaluation, local adapter training, rollback, and provenance.
- Model-weight licenses and training-data rights are separate from framework licenses and must be checked for every Amelia academy/export job.

## Are there projects explicitly combining psychological architecture with memory and fine-tuning?

### Takeaway
Yes, but the field is early. MemoryBank/SiliconFriend is the clearest published memory-plus-psychological-fine-tuning precedent; Familiar-AI is the closest explicit cognitive/affective architecture. Neither appears to be a mature product foundation comparable to the mainstream infrastructure projects.

### Cited Findings
- The **MemoryBank** paper proposes retrieval, continuous memory updating, personality adaptation, and forgetting/reinforcement inspired by the Ebbinghaus curve. Its **SiliconFriend** companion was LoRA-tuned for three epochs at rank 16 on 38k Chinese psychological dialogues, with ChatGLM and BELLE checkpoints released. — [Paper](https://ar5iv.labs.arxiv.org/html/2305.10250v2); [repository](https://github.com/zhongwanjun/MemoryBank-SiliconFriend)
- The paper reports qualitative real-user dialogue analysis and simulated long-dialogue evaluation, but its evidence does not establish production safety, generalization to current models, or longitudinal mental-health outcomes. — [Paper](https://ar5iv.labs.arxiv.org/html/2305.10250v2)
- **Familiar-AI** describes an embodied companion loop in which perception, memory, appraisal, relationship state, drives, and response policy update one another. Its SQLite memory graph includes observations, facts, policies, revisions, episodes, associations, activation, consolidation, and unfinished business, with revision history rather than silent overwrite. — [Technical architecture](https://github.com/lifemate-ai/familiar-ai/blob/develop/docs/technical.md); [repository](https://github.com/lifemate-ai/familiar-ai)
- **ZifaMem** explicitly targets emotional long-term memory with reinforcement, weakening, merging, reflection, and forgetting; its own README labels the implementation alpha and says the full growth loop is unfinished. — [Repository](https://github.com/zifacorp/zifamem)
- **Nomi** and **Kindroid** expose psychologically resonant constructs—identity core, backstory, relationship concepts, key memories, journals, layered recall—but are hosted proprietary products and publish product behavior rather than reproducible cognitive architectures or personal fine-tuning pipelines. — [Nomi Mind Map](https://wiki.nomi.ai/Mind_Map_2.0); [Kindroid memory](https://kindroid.ai/v2/docs/memory/)

### Inferences
- Amelia's strongest technical inspiration is a combination: Familiar-AI's explicit appraisal/relationship loop, MemoryBank's decay/reinforcement hypothesis, Letta's persistent editable identity blocks, and Graphiti's temporal provenance.
- Psychological labels should not be treated as proof of psychological validity. Amelia needs falsifiable state transitions, user-visible evidence, safety boundaries, and evaluations for consistency, recall, overconfidence, dependency risks, and unwanted personality drift.
- Fine-tuning should shape stable conversational skills/style only after curation; mutable user facts and current relationship state belong in inspectable memory, not model weights.

### Gaps
- No strong independent evidence was found that a local companion combining cognitive architecture, autobiographical memory, and per-user fine-tuning improves wellbeing or relationship quality.
- Dataset provenance and consent for SiliconFriend's scraped “online” psychological dialogues are not sufficiently documented in the reviewed paper for direct reuse.
- Familiar-AI and ZifaMem need code-level maturity, license, test coverage, and maintenance review before dependency adoption.

## What is commodity infrastructure versus Amelia's defensible product idea?

### Takeaway
Infrastructure is not the moat. Amelia's defensibility can come from the coherent user-owned lifecycle connecting identity, cognitive state, memory provenance, curriculum, evaluation, and optional model adaptation—especially if it remains understandable and reversible.

### Cited Findings
- Durable graphs, checkpoints, pause/resume, and human state inspection are already provided by LangGraph, CrewAI, and Microsoft Agent Framework. — [LangGraph overview](https://docs.langchain.com/oss/python/langgraph/overview); [CrewAI flows](https://docs.crewai.com/v1.15.28/en/concepts/flows); [Microsoft Agent Framework 1.0](https://devblogs.microsoft.com/agent-framework/microsoft-agent-framework-version-1-0/)
- Memory CRUD, semantic retrieval, and temporal graph retrieval are already available through Mem0, Letta, and Graphiti. — [Mem0 REST API](https://docs.mem0.ai/open-source/features/rest-api); [Letta archival memory](https://docs.letta.com/v1-sdk/memory/archival-memory/); [Graphiti overview](https://help.getzep.com/graphiti/getting-started/welcome.mdx)
- Local model access, chat UX, documents, RAG, and tools are already mature in Open WebUI, LibreChat, AnythingLLM, Khoj, and LobeChat. — [Open WebUI repository](https://github.com/open-webui/open-webui/); [LibreChat repository](https://github.com/danny-avila/LibreChat/); [AnythingLLM repository](https://github.com/Mintplex-Labs/anything-llm/); [Khoj repository](https://github.com/khoj-ai/khoj/); [LobeChat repository](https://github.com/lobehub/lobe-chat)
- Adapter/post-training pipelines are already mature in LLaMA-Factory and Axolotl. — [LLaMA-Factory repository](https://github.com/hiyouga/LLaMA-Factory/); [Axolotl docs](https://docs.axolotl.ai/)

### Inferences
- **Commodity:** model routing/serving, chat rendering, embeddings/vector stores, parsers, RAG, tool/MCP plumbing, workflow persistence, LoRA execution, and generic observability.
- **Potentially defensible:** a stable companion identity with explicit invariants; a cognitive/appraisal pipeline whose state transitions are inspectable; autobiographical memory with evidence, temporal validity, contradiction handling, consent, and decay; a user-curated academy with lineage and rights metadata; evaluation gates before memory promotion or training; and safe reversible migration between base models.
- Amelia should differentiate through the *contract between layers*: what can change, who may change it, what evidence supports it, what reaches prompts, what reaches training, and how the user audits or rolls it back.
- Stable identity should be represented as versioned policy/persona state, not inferred solely from accumulated chat. Memory should inform identity evolution through explicit proposals and approval, avoiding silent persona drift.
- “Local-first” is only defensible if export, backup, deletion, offline operation, and migration are complete product capabilities rather than a local Ollama checkbox.

### Gaps
- Defensibility ultimately depends on execution, trust, data governance, and longitudinal UX; architecture alone is readily reproducible.
- Patent, trademark, and freedom-to-operate analysis was outside this research.

## Which components are mature enough to adopt, and what should Amelia borrow or avoid?

### Takeaway
Adopt permissively licensed infrastructure behind Amelia-owned interfaces. Prototype memory backends against Letta, Mem0, and Graphiti before committing. Do not fork a large chat product or bind the domain model to a hosted control plane.

### Cited Findings
- LangGraph deliberately supplies low-level orchestration without prescribing prompts or architecture, making it suitable for Amelia's custom deterministic/LLM cognitive stages. — [Official overview](https://docs.langchain.com/oss/python/langgraph/overview)
- Letta supplies persistent agent state, editable identity/human blocks, archival retrieval, inspection tooling, and a current git-backed memory model. — [Memory blocks](https://docs.letta.com/v1-sdk/memory/memory-blocks/index.md); [current memory docs](https://docs.letta.com/agent-sdk/memory/index.md)
- Graphiti supplies temporal facts, provenance, incremental ingestion, invalidation, and hybrid retrieval, but explicitly leaves service concerns such as tenancy and operations to the adopter. — [Repository](https://github.com/getzep/graphiti)
- Mem0 supplies a small self-hostable REST/SDK surface with edit/delete/history operations. — [OSS REST server](https://docs.mem0.ai/open-source/features/rest-api)
- LLaMA-Factory and Axolotl already cover the expensive mechanics of local LoRA/QLoRA and preference tuning. — [LLaMA-Factory repository](https://github.com/hiyouga/LLaMA-Factory/); [Axolotl docs](https://docs.axolotl.ai/)
- AutoGen is archived, and Semantic Kernel is in minimal-maintenance transition to Microsoft Agent Framework; beginning new Amelia code on either would knowingly adopt a migration path. — [AutoGen notice](https://github.com/microsoft/autogen/); [Semantic Kernel maintenance statement](https://github.com/microsoft/semantic-kernel/pull/13932)

### Inferences
- **Adopt now:** Ollama/llama.cpp-compatible inference; a simple local SQL store for canonical state; mature parsers/embeddings; LangGraph for the introspective pipeline if Python is acceptable; LLaMA-Factory or Axolotl as an out-of-process training worker; standard tracing plus a dedicated Amelia evaluation suite.
- **Prototype before choosing:** Letta when agent-managed identity and memory inspection are primary; Mem0 when low-complexity memory CRUD is primary; Graphiti when contradiction, event chronology, and relationships justify a graph database. A hybrid canonical SQL event log plus derived vector/graph indexes may preserve portability best.
- **Borrow from companion products:** visible memory panels (Replika), stable identity/backstory controls and layered recall (Nomi/Kindroid), and user-prioritized memory. Improve them with source evidence, actual underlying-memory editing, history, and rollback.
- **Borrow from Open WebUI:** blind model comparisons and conversation feedback. Do not copy its assumption that snapshots alone constitute a training workflow; Amelia should require curation, redaction, licensing, split management, regression tests, and explicit training consent.
- **Avoid:** AutoGen for new production work; deep coupling to Semantic Kernel; Open WebUI as a white-label base without license review; AGPL Khoj code if Amelia's distribution model is incompatible; opaque hosted memory; silently self-modifying persona; training on raw private chats; storing changing facts in weights; and multi-agent complexity where an explicit single-agent state graph is sufficient.
- **Suggested component boundary:** Amelia owns identity schema, cognitive state machine, memory event/provenance model, academy records, consent, and evaluations. Replaceable adapters handle chat UI, model runtime, embedding/vector/graph projections, document extraction, orchestration runtime, and fine-tuning worker.

### Gaps
- A short proof-of-concept benchmark is still needed using Amelia-like conversations: correction handling, contradiction over time, provenance retrieval, latency on local hardware, backup/export, and memory deletion propagation across derived indexes.
- Before production adoption, pin exact versions and perform dependency/security review; current activity and permissive licenses do not guarantee API stability.
